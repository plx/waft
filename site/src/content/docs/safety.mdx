`waft` separates read-only planning from file publication. Only `copy`
without `--dry-run` publishes files.

## Guarantees

- **Tracked files are not overwritten.** Tracked status is checked during
  planning and again under Git's index lock before publication.
- **Existing paths are not replaced by default.** Publication uses no-clobber
  semantics. Only `--overwrite` replaces an untracked destination, and only
  after proving it is still the file that was planned against.
- **Symlink traversal is blocked on Unix.** Source and destination components
  are opened relative to canonical worktree directory handles with
  `O_NOFOLLOW`.
- **Files are prepared before publication.** Contents are synced to a temporary
  file, and parent directories are synced on Unix. Atomic exchange is used
  where supported. Its fallback can leave a temporary gap at the destination
  and named recovery files. A batch is not an atomic transaction.
- **Dry runs are mutation-free.** `waft copy --dry-run` reads and reports only.

## Concurrent changes

Normal Git writers honor the index lock and cannot change trackedness across
the final check and publication. Direct index edits that ignore Git's lock
protocol are outside this guarantee.

On Unix, directory handles prevent symlink or name swaps from redirecting a
write. Another process can still relocate an already-open destination
directory after final revalidation. Avoid concurrent destination directory
moves when pathname stability matters.

`waft` reacquires the index lock for each published file and reuses a cached
tracked-path snapshot while the index fingerprint stays unchanged. A changed
index triggers a reload. This avoids re-reading the entire index for every
file; keep automatic manifests narrow and benchmark your own workload.

## Hook trust boundary

Install the optional post-checkout hook only from a reviewed revision.
`just install-hooks` copies the hook and a pinned `waft` binary into Git's
common metadata directory and configures an absolute hook path. It rejects
symlinked prior hooks and worktree-specific hook overrides.

The hook runs its pinned binary with `--isolated`. Ambient `WAFT`, user config,
and `WAFT_*` policy variables cannot change automatic execution or selection.
Source-project configuration still applies.

Do not set `core.hooksPath` to a directory inside a checked-out worktree.
Branches can replace tracked hook content before Git invokes it.

## Secrets remain secrets

Every selected file becomes another filesystem copy. Backup software,
indexers, local agents, and anyone who can read the linked worktree may see it.
Use secret injection or short-lived credentials for high-value secrets.

## Preview before writing

```sh
waft copy --dry-run
```

Review the selected files and the reason for each decision.

## Overwrite behavior

Without `--overwrite`, an existing destination is preserved exactly as it is.
The run names every file it skipped and why, and still exits 0:

```text
skip: .env (untracked conflict; --overwrite replaces the destination)
```

`--overwrite` acts on untracked destinations only, and distinguishes two
cases:

- **untracked conflict** — the content differs. The replacement is prepared in
  a temporary file and exchanged atomically where supported, with a checked
  displacement/no-clobber fallback otherwise, reported as `replaced:`.
- **content equal, permissions differ** — only the mode is wrong. The mode is
  repaired on the verified file descriptor and no content is rewritten,
  reported as `repaired permissions:`.

```sh
waft copy --overwrite
```

Both actions check the destination against the identity, length, content
fingerprint, and mode observed while planning. A detected change is a per-file
failure. Depending on when the change is detected, recovery restores the
displaced file or preserves it at a named recovery path when restoring would
clobber a later writer. Cleanup failures name surviving recovery paths.
The rest of the run continues. Tracked destinations are checked under the
index lock with or without the flag.

Windows has no supported overwrite or permission-repair path. Unix signal
cleanup attempts to remove owned index locks on `SIGINT` and `SIGTERM`, but
staging files can survive termination. Crashes and `SIGKILL` can leave stale
locks as well. Inspect recovery files and establish that no Git writer is
active before removing a stale lock.
