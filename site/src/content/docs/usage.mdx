`waft` copies selected Git-ignored files from the main worktree to a linked
worktree in the same repository. By default, it leaves existing destination
files alone.

## Installation

`waft` is not published to crates.io. Install a reviewed commit from Git:

```sh
cargo install --git https://github.com/plx/waft \
  --rev REVIEWED_COMMIT_SHA --locked waft
```

Replace `REVIEWED_COMMIT_SHA` with the full SHA of the commit you reviewed.

## Quick start

1. Add `.worktreeinclude` at the root of the main worktree. For example, to
   copy local environment files:

   ```text
   .env
   *.env.local
   ```

   These files must already exist and be ignored by Git. Listing a tracked
   file here does not make it eligible.

2. From a linked worktree, preview the copy:

   ```sh
   waft copy --dry-run
   ```

3. Review the plan, then copy:

   ```sh
   waft copy
   ```

From a linked worktree, the source and destination are automatic. To name
them explicitly:

```sh
waft copy --source /path/to/main --dest /path/to/linked
```

The source must be the main worktree. From there, pass `--dest` to choose a
linked worktree. `waft` does not create worktrees or copy between repositories.

With the default profile, a missing `.worktreeinclude` selects nothing. Use
`waft info .env` to check why a file is selected or skipped. See
[file selection](../worktreeinclude/) for matching rules.

## Commands

| Command               | Description                                       |
| --------------------- | ------------------------------------------------- |
| `waft` / `waft copy`  | Copy eligible files. This is the default command. |
| `waft list`           | List eligible files without copying.              |
| `waft info <PATH>...` | Show detailed status for specific files.          |
| `waft validate`       | Check `.worktreeinclude` and Git ignore syntax.   |

## Global options

| Option                                          | Description                                                 |
| ----------------------------------------------- | ----------------------------------------------------------- |
| `--source <PATH>`                               | Source, usually the main worktree path.                     |
| `--dest <PATH>`                                 | Destination, usually the linked worktree path.              |
| `-C <PATH>`                                     | Operate as if started in `PATH`.                            |
| `-q, --quiet`                                   | Suppress non-error output.                                  |
| `-v, --verbose`                                 | Increase output verbosity.                                  |
| `--copy-strategy <auto\|simple-copy\|cow-copy>` | Select plain-copy or copy-on-write behavior.                |
| `--isolated`                                    | Omit user config and `WAFT_*` policy environment variables. |

## Copy options

| Option          | Description                                                                                                                       |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `-n, --dry-run` | Show what would be done without copying.                                                                                          |
| `--overwrite`   | Replace untracked destinations that differ, and repair untracked destinations whose content matches but whose permissions do not. |

## Copy output

A copy run reports each published file (`copied:`, `replaced:`,
`repaired permissions:`) and each file it left alone, with the reason:

```text
skip: .env (untracked conflict; --overwrite replaces the destination)
```

Skips are not failures; the run still exits 0. `--quiet` suppresses all of it
except per-file failures.

If the active configuration selects nothing and no `.worktreeinclude` was
consulted, `copy`, `list`, and `info` say so once on standard error:

```text
note: no .worktreeinclude found; the claude profile selects nothing without one (see waft validate)
```

The note names whatever is responsible, so it also covers a rule file that
exists but is never read — one outside the repository root under root-only
`claude-2026-04` semantics, or a symlinked one under
`--worktreeinclude-symlink-policy ignore`. A consulted rule file that
legitimately matches nothing is not flagged. Standard output stays
machine-readable, and `--quiet` suppresses the note. Symlink hints ask you to
inspect targets and validate with the intended settings. They do not promise
that changing policy will validate or select files.

See [Configuration](../configuration/) for profile, exclusion, and config-file
options, and [Safety](../safety/) for conflict handling.

## Optional post-checkout hook

Install the repository's post-checkout hook from a reviewed source checkout:

```sh
just install-hooks
```

The installer builds `waft`, copies the binary and hook into the repository's
common Git directory, and configures an absolute `core.hooksPath`. The hook
uses the pinned binary with `--isolated`; source-project configuration still
applies. The installer refuses symlinked prior hooks and worktree-specific
hook overrides.

Reinstall the hook after upgrading `waft`. Remove it and restore the previous
hook configuration with:

```sh
just uninstall-hooks
```

Do not point `core.hooksPath` at the tracked `hooks/` directory. A checked-out
branch can replace that directory before Git runs the hook.
