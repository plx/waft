`waft` copies `.worktreeinclude`-selected ignored files between Git worktrees.

## Installation

`waft` is not currently published to crates.io. Install a reviewed commit
directly from Git:

```sh
cargo install --git https://github.com/plx/waft \
  --rev REVIEWED_COMMIT_SHA --locked waft
```

Replace `REVIEWED_COMMIT_SHA` with the full revision you reviewed. Managed
environments should not omit `--rev`.

It is intended for local configuration, caches, and tool state that Git should
not track but that developers often need in more than one linked worktree.

## Quick start

```sh
# In a linked worktree, copy from the main worktree automatically.
waft

# Explicit source and destination.
waft copy --source /path/to/main --dest /path/to/linked

# See what would be copied without writing files.
waft copy --dry-run

# List eligible files.
waft list

# Inspect specific files.
waft info .env

# Validate ignore files.
waft validate
```

## Commands

| Command               | Description                                       |
| --------------------- | ------------------------------------------------- |
| `waft` / `waft copy`  | Copy eligible files. This is the default command. |
| `waft list`           | List eligible files without copying.              |
| `waft info <PATH>...` | Show detailed status for specific files.          |
| `waft validate`       | Check ignore files for syntax errors.             |

## Global options

| Option            | Description                                    |
| ----------------- | ---------------------------------------------- |
| `--source <PATH>` | Source, usually the main worktree path.        |
| `--dest <PATH>`   | Destination, usually the linked worktree path. |
| `-C <PATH>`       | Operate as if started in `PATH`.               |
| `-q, --quiet`     | Suppress non-error output.                     |
| `-v, --verbose`   | Increase output verbosity.                     |

## Copy options

| Option          | Description                                                  |
| --------------- | ------------------------------------------------------------ |
| `-n, --dry-run` | Show what would be done without copying.                     |
| `--overwrite`   | Compatibility flag; fails on existing destination conflicts. |

## Typical flow

1. Add `.worktreeinclude` to the source repo.
2. Run `waft copy --dry-run`.
3. Inspect the plan.
4. Run `waft copy`.
5. Use `waft info <path>` when a file is missing or skipped.

## Optional post-checkout hook

From a reviewed source checkout:

```sh
just install-hooks
```

This builds `waft` and snapshots both the binary and post-checkout hook under
the repository's common Git directory. The absolute managed hook directory
chains the previously effective trusted Git hooks; checked-out branches
cannot replace the installed snapshot. Automatic copies use `--isolated`, so
the pinned sibling binary cannot be replaced through ambient `WAFT`, and user
config or `WAFT_*` policy variables cannot alter selection. The installer
refuses symlinked prior hooks and worktree-scoped hook overrides in every
extant linked worktree. Trusted project config from the source worktree still
applies. Re-run the command after upgrading.

Never point `core.hooksPath` directly at the tracked `hooks/` directory.
Branch-controlled content in that directory may execute during checkout.

Restore the prior hook configuration with `just uninstall-hooks`.
