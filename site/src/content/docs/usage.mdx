`waft` copies selected ignored files from one Git worktree to another. Use it
for local configuration, caches, and tool state that you need in more than one
worktree but do not want to commit.

## Installation

`waft` is not published to crates.io. Install a reviewed commit from Git:

```sh
cargo install --git https://github.com/plx/waft \
  --rev REVIEWED_COMMIT_SHA --locked waft
```

Set `REVIEWED_COMMIT_SHA` to the full commit SHA. Keep `--rev` in managed
environments.

## Quick start

1. Add `.worktreeinclude` to the source worktree:

   ```text
   .env
   *.env.local
   ```

2. From a linked worktree, preview the copy:

   ```sh
   waft copy --dry-run
   ```

3. Review the plan, then copy:

   ```sh
   waft copy
   ```

When run from a linked worktree, `waft` uses the main worktree as the source
and the current worktree as the destination. Pass both paths to override that
resolution:

```sh
waft copy --source /path/to/main --dest /path/to/linked
```

## Commands

| Command               | Description                                       |
| --------------------- | ------------------------------------------------- |
| `waft` / `waft copy`  | Copy eligible files. This is the default command. |
| `waft list`           | List eligible files without copying.              |
| `waft info <PATH>...` | Show detailed status for specific files.          |
| `waft validate`       | Check `.worktreeinclude` and Git ignore syntax.   |

## Global options

| Option                                          | Description                                                 |
| ----------------------------------------------- | ----------------------------------------------------------- |
| `--source <PATH>`                               | Source, usually the main worktree path.                     |
| `--dest <PATH>`                                 | Destination, usually the linked worktree path.              |
| `-C <PATH>`                                     | Operate as if started in `PATH`.                            |
| `-q, --quiet`                                   | Suppress non-error output.                                  |
| `-v, --verbose`                                 | Increase output verbosity.                                  |
| `--copy-strategy <auto\|simple-copy\|cow-copy>` | Select plain-copy or copy-on-write behavior.                |
| `--isolated`                                    | Omit user config and `WAFT_*` policy environment variables. |

## Copy options

| Option          | Description                                                  |
| --------------- | ------------------------------------------------------------ |
| `-n, --dry-run` | Show what would be done without copying.                     |
| `--overwrite`   | Compatibility flag; fails on existing destination conflicts. |

## Inspect selection

```sh
waft list
waft info .env
waft validate
```

`list` prints eligible files. `info` explains why specific paths are selected
or skipped. `validate` checks rule files without copying.

## Optional post-checkout hook

Install the repository's post-checkout hook from a reviewed source checkout:

```sh
just install-hooks
```

The installer builds `waft`, copies the binary and hook into the repository's
common Git directory, and configures an absolute `core.hooksPath`. The hook
uses the pinned binary with `--isolated`; source-project configuration still
applies. The installer refuses symlinked prior hooks and worktree-specific
hook overrides.

Reinstall the hook after upgrading `waft`. Remove it and restore the previous
hook configuration with:

```sh
just uninstall-hooks
```

Do not point `core.hooksPath` at the tracked `hooks/` directory. A checked-out
branch can replace that directory before Git runs the hook.
