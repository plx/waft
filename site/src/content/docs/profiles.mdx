Profiles control how `.worktreeinclude` is interpreted. The default is
`claude`. Use `git` for nested rule files or `wt` for the Worktrunk behavior
described below.

```sh
waft copy --compat-profile git --dry-run
```

## `claude`

`claude` is the default. It reads only the repository root
`.worktreeinclude` and matches the observed Claude Code behavior identified by
`claude-2026-04`.

## `git`

`git` applies per-directory exclude semantics. Patterns are relative to the
directory containing the rule file, and deeper rule files override shallower
ones.

## `wt`

`wt` matches the observed Worktrunk behavior identified by `wt-0.39`. It starts
with every ignored, untracked file, even without `.worktreeinclude`, and removes
paths matched by literal-name negations. Positive patterns and glob negations
are ignored. The `tooling-v1` exclusion set also removes tool state such as
`.claude/` and `.conductor/`.

These are versioned compatibility behaviors, not a promise to match future
Claude Code or Worktrunk releases. [Configuration](../configuration/) lists
the individual overrides.
