`waft` uses Git to check file status, `.worktreeinclude` to select files, and a
copy plan to separate those reads from writes.

## Git backends

The `GitBackend` trait supplies final ignored and tracked status. `waft` does
not infer either status from `.gitignore` parsing alone.

- `GitGix` is the default in-process backend built on the `gix` crate.
- `GitCli` runs Git commands. Select it with `WAFT_GIT_BACKEND=cli`.

## File matching

`worktreeinclude_engine` applies `.worktreeinclude` rules independently of the
Git backend. It provides three matchers:

- `claude-2026-04`, the default root-rule-file behavior.
- `git`, Git-style per-directory exclude semantics.
- `wt-0.39`, worktrunk-compatible subtractive behavior.

## Command pipeline

The pipeline is read-only through copy planning.

1. Parse CLI arguments.
2. Resolve source and destination worktree context.
3. Resolve layered policy against that source worktree.
4. Validate ignore files.
5. Select candidate files.
6. Apply policy filters.
7. Confirm ignored status through Git.
8. Build a copy plan.
9. For `copy` without `--dry-run`, verify planned state and publish each file.
   An existing pathname is replaced only under `--overwrite`, only when it is
   untracked, and only after it still matches the state recorded while
   planning.

`validate` stops after rule parsing. `list` and `info` stop after
classification. `copy --dry-run` stops after planning.

The planner and executor live in `src/planner.rs` and `src/executor.rs`.
See [Safety](../safety/) for the checks made before each write.
